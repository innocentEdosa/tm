## Dependencies & Execution Order

### Phase Dependencies

- **Setup (Phase 1)**: No dependencies - already complete.
- **Foundational (Phase 2)**: Depends on Setup - BLOCKS all user stories.
- **User Stories (Phase 3-7)**: All depend on Foundational completion.
  - US1 → US2: US2's content/file routes attach to platform courses US1 creates, and reuse T011/T012 from Foundational, but US2's *tables* (T002) are foundational, so US2 could theoretically start in parallel with US1 if staffed — sequenced here because US2's UI (T023) extends US1's UI (T017).
  - US3 depends on US1+US2 existing (browses what they create) but is its own independently-testable read surface.
  - US4 depends on US1+US2+US3 (clones what US3 lets a tenant find) and on T028's clone function.
  - US5 depends on US4 (T028's clone function, T029's select endpoint) — extends the same select action to the paid branch.
- **Polish (Phase 8)**: Depends on all five user stories being complete (T038 spans US1/US2's endpoints; T039 spans US3/US4/US5's data).

### Within Each User Story

- Backend handlers before their integration test before their UI task.
- Story complete (backend + test + UI) before moving to next priority.

### Parallel Opportunities

- T003, T007, T008, T010, T011, T012 (Foundational) can run in parallel with each other where marked [P].
- T016, T022, T026, T030, T035, T039 (integration tests) can run in parallel with unrelated stories' work once their own story's handlers are done.
- US1 and US3's *reads* have no write-order dependency on each other beyond needing Foundational + US1's create endpoint to have data to browse — in practice sequenced by priority as listed.
